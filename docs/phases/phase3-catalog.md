# Phase 3 — Catalog

Service: `services/catalog/`. See `docs/modules/catalog/README.md`.

Owns the master catalogue, product definitions, the 4-layer availability cascade,
flavour options, add-ons, occasions, and seasonal schedules.

## 3.2 Availability cascade resolution

Resolved in a **single query** (no N+1). Called at: storefront product listing,
product configuration page, slot picker, order creation validation.

```sql
-- Pseudo-SQL — actual query is generated by sqlc
SELECT
  p.id, p.name, p.is_active AS master_active,
  COALESCE(
    -- Layer 4: date override (highest priority)
    date_override.enabled,
    -- Layer 3: weekly schedule
    weekly.enabled,
    -- Layer 2: branch setting
    branch_setting.enabled,
    -- Layer 1: master catalogue (fallback)
    p.is_active
  ) AS effective_available,
  -- Next available date if currently unavailable
  ...
FROM products p
LEFT JOIN branch_catalog_overrides date_override ON
  date_override.product_id = p.id
  AND date_override.branch_id = $branch_id
  AND date_override.override_type = 'date_override'
  AND date_override.override_date = CURRENT_DATE AT TIME ZONE $branch_timezone
LEFT JOIN branch_catalog_overrides weekly ON
  weekly.product_id = p.id
  AND weekly.branch_id = $branch_id
  AND weekly.override_type = 'weekly_schedule'
  AND weekly.day_of_week = EXTRACT(DOW FROM CURRENT_TIMESTAMP AT TIME ZONE $branch_timezone)
LEFT JOIN branch_catalog_overrides branch_setting ON
  branch_setting.product_id = p.id
  AND branch_setting.branch_id = $branch_id
  AND branch_setting.override_type = 'branch_setting'
WHERE p.category_id = $category_id
```

**CAT-06 compliance**: availability change propagates to storefront within 30 seconds.
On any `branch_catalog_overrides` write → `realtime` emits `catalog.availability_changed`
event → storefront invalidates its cache via SSE (no manual cache clear needed).

## 3.3 Product configuration API (storefront-facing)

```
GET  /v1/catalog/categories                     → 3 categories with counts
GET  /v1/catalog/categories/{slug}/products     → products with availability (branch scoped)
GET  /v1/catalog/products/{id}                  → full product detail
GET  /v1/catalog/products/{id}/variants         → size variants with prices
GET  /v1/catalog/products/{id}/flavours         → flavour options with allergen info
GET  /v1/catalog/products/{id}/addons           → available add-ons (branch-scoped in R2)
GET  /v1/catalog/occasions                      → occasion list (for nav + landing pages)
GET  /v1/catalog/occasions/{slug}/products      → occasion-filtered products
```

All storefront catalog endpoints require `branch_id` query param — resolved from ZIP/pickup
before any product browsing begins.
